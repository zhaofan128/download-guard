# 截图规格与拍摄脚本

> **这些图我无法代拍。** 商店要求真实运行截图，用设计稿或合成图冒充会被判「截图与实际功能不符」，直接驳回。下面给的是拍摄清单与规格，真机跑一遍即可。

## 一、规格

| 商店 | 数量 | 尺寸 | 格式 | 备注 |
|---|---|---|---|---|
| 华为 | 3–8 张 | 1080×1920 或 1440×2560，比例 9:16 | JPG/PNG ≤ 5 MB | 首图最重要 |
| 小米 | 3–5 张 | 1080×1920 起 | JPG/PNG | 不接受带其他商店水印 |
| OPPO / vivo | 3–5 张 | 1080×1920 起 | JPG/PNG | 横竖屏需一致 |
| 应用宝 | 3–5 张 | 1080×1920 起 | JPG/PNG | 审核最严，勿含版权内容 |
| Google Play | 2–8 张 | 16:9 或 9:16，最短边 ≥ 320 px | PNG/JPG | 另需 1024×500 宣传图 |

通用要求：

- 全部竖屏，同一台设备、同一套主题（建议浅色或深色只选一种）
- 状态栏干净：不要出现未读消息、其他应用图标、运营商以外的个人信息
- 不出现手机号、真实姓名、聊天内容、其他商店 Logo、影视/游戏画面
- 截图里的文件名用中性示例（`example-video.mp4`、`archive.zip`），不要用真实版权作品名
- 不要加「下载破解版」「会员加速」之类文案

## 二、拍摄脚本（5 张）

### 图 1：首页 + 下载中

1. 打开应用，输入一个可公开访问的测试直链（例如 `https://speed.cloudflare.com/__down?bytes=104857600`）
2. 点开始，等进度到 30%–60%
3. 再添加一个任务，让列表出现 2 条不同进度的任务
4. 截图

要点：能同时看到「输入框 + 高级折叠区 + 多任务进度」。

### 图 2：网页嗅探

1. 首页点「网页模式」或从分享入口进入嗅探页
2. 打开一个公开的下载站页面（不要用需要登录的网盘）
3. 等页面加载完、底部出现候选链接列表
4. 截图

要点：展示「页面 + 抓到的直链候选」同屏。

### 图 3：站点规则列表

1. 设置 → 站点规则
2. 新建 2 条示例规则：`example.com`、`*.example.net`
3. 截图

要点：显示域名、优先级、Cookie 来源、并发数，不要显示自定义 Cookie 的值。

### 图 4：规则测试结果

1. 打开任意一条规则 → 点「测试」
2. 填入 `https://dl.example.com/file.zip` 与页面地址
3. 让结果区显示「命中规则 / Referer / Cookie: name=***」
4. 截图

要点：证明规则是「声明式、可预览、不联网」，Cookie 已脱敏。

### 图 5：设置页

1. 设置页顶部
2. 截图

要点：展示「站点规则」「下载并发」「仅 Wi-Fi」等常规项。无障碍开关（「浏览器链接识别」）**可以且建议**出现在图里——它是可见、可关的，藏着反而像在隐瞒；但不要出现 Shizuku / 接力 / 跨应用抓取入口（商店版本就没有）。

如果商店要求单独提供无障碍功能说明，补一张「点击开关 → 弹出用途说明」的截图，配文用 `permissions.md` 第 7 节的话术。

## 三、拍摄命令（真机）

```bash
# 连上手机后
adb exec-out screencap -p > shot-01.png

# 批量导出后统一裁掉状态栏（可选，保留系统状态栏更真实）
# 建议保留状态栏，只把通知图标清干净
```

尺寸不够时不要拉伸，用系统「分辨率」或模拟器同比例重拍。

## 四、首图建议

首图决定点击率。建议用「图 1」，并在商店后台的「特色图文」里配一句：

> 多线程 + 断点续传，退到后台也不断

如果商店允许在截图上加文字（华为、小米支持），字号不小于 48 px，只放一行，不要遮挡进度条。
