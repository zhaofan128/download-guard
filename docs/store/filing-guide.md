# 备案与上架指引

> 这一份是操作路径，不是承诺。**实名、人脸核验、签章、提交按钮必须你本人操作**——任何声称能代办的渠道都在拿你的身份信息冒险。
> 政策会变，提交前以接入服务商与商店后台的实时提示为准。

## 一、三样东西别搞混

| 名称 | 是什么 | 谁发 | 用途 | 能不能省 |
|---|---|---|---|---|
| **软件著作权**（软著） | 代码的权属证明 | 中国版权保护中心 | 商店「资质证明」环节，证明这个 App 是你的 | 主流商店基本都要 |
| **APP 备案** | 行政合规手续 | 各省通信管理局（经接入服务商提交） | 证明 App 的主体与内容合法 | 硬门槛，没有会被下架 |
| **隐私政策 URL** | 公网可访问的页面 | 你自己发布 | 商店后台必填项 | 硬门槛 |

三者主体必须一致：**软著著作权人 = 备案主体 = 开发者账号主体**。不一致会被要求补充授权说明，很拖时间。

## 二、软件著作权

**渠道**：中国版权保护中心 `ccopyright.com.cn`，或各省版权局代办。

**材料**：

- 申请表（在线填写后打印签字）
- 源代码：前 30 页 + 后 30 页，每页 50 行，共 60 页（不足 60 页全部提交）
- 软件说明书：功能、运行环境、操作流程，配截图
- 身份证明：个人交身份证复印件签字；企业交营业执照副本复印件盖章

**周期与费用**：普通 30–45 个工作日，加急 5–30 个工作日（费用 300–1500 元不等）。自己办免费。

**名称注意**：软著名称要与商店填写的应用名一致或高度近似。「下载守护」建议软著全称写「下载守护下载器软件」，商店用简称「下载守护」，并在备注里说明对应关系。

## 三、APP 备案

### 3.1 前置条件

1. **主体**：个人或企业。个人主体仅限非经营性工具类，不能涉及新闻、出版、视听、社交、电商等强监管领域。本项目是下载工具，符合。
2. **接入服务商**：必须通过一家有资质的接入商提交（阿里云、腾讯云、华为云、天翼云等）。
3. **服务器**：传统要求是「服务器在中国大陆，且在所选接入商名下」。
   > **本项目的特殊情况**：这是纯本地应用，没有后端服务器，也不要求用户登录。这种情况在备案系统里通常按「无服务器 / 仅客户端」处理，但**各省管局与各接入商的受理口径不一致**：有的要求必须有一个已备案域名，有的接受「无域名纯客户端」并让你上传安装包或应用商店链接。提交前先在该接入商的备案控制台看「APP 备案」表单是否强制要求域名；如果强制，最省事的做法是买一台最低配的境内云服务器 + 一个域名，做一次空站备案，再关联 APP。
4. **隐私政策**：公网 HTTPS 可访问，内容与 App 实际行为一致。

### 3.2 材料清单

| 材料 | 说明 |
|---|---|
| 主体证件 | 个人：身份证正反面 + 手持照；企业：营业执照 |
| 负责人信息 | 姓名、身份证号、手机号、邮箱（需短信核验） |
| APP 名称 | 与软著、商店一致 |
| 包名 | `com.dlguard` |
| 签名 MD5 | 见下方命令，**去掉冒号、小写** |
| APP 公钥 | 见下方命令，Base64 字符串 |
| 隐私政策 URL | 公网可访问 |
| 安装包或商店链接 | 部分接入商要求 |
| 承诺书 / 核验单 | 系统生成后本人签字（个人）或盖章（企业） |

### 3.3 取签名 MD5 与公钥

```bash
APK=app/build/outputs/apk/store/release/app-store-release.apk
APKSIGNER=$(ls $ANDROID_HOME/build-tools/*/apksigner | tail -1)

# 证书信息（含 SHA-256 / SHA-1 / MD5 指纹）
$APKSIGNER verify --print-certs "$APK"

# 只要 MD5（备案系统要的格式：无冒号）
keytool -printcert -jarfile "$APK" | grep "MD5:" | sed 's/.*MD5: //; s/://g' | tr 'A-Z' 'a-z'

# APP 公钥（Base64，DER 编码）
keytool -exportcert -keystore <你的 keystore> -alias <别名> -storepass <密码> \
  | base64 -w 0
```

> 用错了密钥会导致「备案信息与安装包不一致」，上线后检测到会要求重新备案。**务必用最终发布的那个 keystore**。

### 3.4 流程

1. 登录接入商备案控制台 → 新增「APP」备案
2. 填主体信息 → 填 APP 信息（包名、签名、公钥、隐私政策）→ 上传材料
3. 接入商初审（1–2 工作日），可能电话核验
4. 转属地通信管理局复审（5–20 工作日）
5. 通过后获得备案号，格式如 `京ICP备XXXXXXXX号-XXA`
6. **把备案号填进 App 内**（设置页「关于」）和商店后台

> 本项目已在设置页「关于」区块预留版本信息位置，备案号拿到后需要补一行文本并重新构建。这一步我可以帮你改，但要等你拿到号。

## 四、各商店的个人开发者门槛

| 商店 | 个人开发者 | 软著 | 备案 | 备注 |
|---|---|---|---|---|
| 华为应用市场 | 支持 | 要 | 要 | 个人开发者部分类目受限，工具类可以 |
| 小米应用商店 | 支持 | 要 | 要 | 首次提审需实名 + 手持身份证 |
| OPPO 软件商店 | 支持 | 要 | 要 | 对下载工具类审核较严，需说明不提供内容源 |
| vivo 应用商店 | 支持 | 要 | 要 | 同上 |
| 应用宝（腾讯） | 支持 | 要 | 要 | 需先注册开发者，可能要企业资质 |
| Google Play | 支持 | 不要 | 不要 | 但无障碍政策极严，本项目的无障碍服务大概率被拒；建议 Play 版再裁一版（去掉无障碍） |

**Google Play 单独提醒**：Play 对 `AccessibilityService` 的政策是「仅限真正帮助残障用户的应用」，下载器抓链接不属于豁免范围，提交后基本会被拒并要求移除。如果要上 Play，需要再出一个不带无障碍的变体。

## 五、审核最可能问的三个问题

**1. 为什么下载器需要无障碍？**

用 `review-notes.md` 第二节的整段答复。核心是三句话：只对浏览器生效、只订阅点击事件、没有 `canPerformGestures`。这三条都能在 APK 里核对。

**2. 是否提供盗版内容？**

> 应用不提供任何内容源、搜索或推荐，只传输用户自己提供的地址；没有「破解」「会员加速」「绕过付费墙」功能。

**3. 为什么需要前台服务？**

> 下载是用户主动发起的长时间任务，切到后台需要继续传输；通知可见、可暂停、可取消。

## 六、时间线建议

```
第 1 周   软著提交（普通通道）+ 隐私政策发布到公网
第 2-6 周 等软著；同时把备案材料准备好
第 3 周   APP 备案提交（可与软著并行，不必等软著下来）
第 6-8 周 软著、备案陆续下来 → 注册/完善开发者账号 → 提审
```

软著和备案可以并行，别串行等。
